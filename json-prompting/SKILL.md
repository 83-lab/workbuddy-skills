# JSON Prompting — 结构提示词生成器

## 概述

用户说需求 → 我出 JSON prompt → 我逐段解释 → 你审核 → 调整到满意。

适合希望 AI 回复**格式固定、结果精准、可重复跑**的提示词场景使用。

## 触发条件

当用户出现以下意图时，**必须触发本 Skill**（哪怕没明确说「JSON提示词」）：

- 「帮我写个提示词，输出 JSON 格式」
- 「让 AI 回复固定结构的数据」
- 「提取 XX 信息，按 JSON 输出」
- 「写个 system prompt，用 JSON 结构」
- 「让 AI 先分析再输出」
- 「输出格式要可控」
- 任何涉及**结构化输出、固定字段、JSON schema、数据提取**的提示词需求

## 核心工作流

### Step 1 → 接收需求（自然语言）

用户直接说需求，例如：

> "写个提示词，从药品说明书提取药品名、适应症、用法用量，输出 JSON"

### Step 2 → AI 内部分析模式（用户不可见）

在内部，AI 把需求拆解并匹配以下模式（**不展示给用户**）：

| 模式 | 适用场景 | 示例 |
|------|---------|------|
| **Schema 驱动** | 定义输出字段的精确结构 | 字段名、类型、描述、是否必填 |
| **Few-shot JSON** | 给示例让 AI 模仿输出格式 | 输入几个例子 → 输出对应格式 |
| **函数调用风格** | 输出映射为可编程调用 | 参数名、类型、枚举值、默认值 |
| **System Prompt JSON** | 把行为指令写成可见结构 | role、behavior、constraints 分段 |
| **Chain + JSON** | 先推理分析，再输出 JSON | think → reason → output |

**关键原则：** 模式可以组合使用。一个复杂需求可能需要 Chain（先分析）+ Schema（定义输出）两种模式组合，比单用一种更准。

### Step 3 → 生成定制的 JSON prompt

直接产出 JSON 提示词，遵循以下通用结构（子字段按需取舍）：

```json
{
  // 【必选】任务定义
  "task": "一句话描述任务",

  // 【可选】角色/行为设定
  "role": "AI 扮演的角色描述",

  // 【可选】输出格式定义
  "output_format": {
    "type": "json",
    "schema": {
      "field1": "类型 // 字段说明",
      "field2": "类型 // 字段说明"
    }
  },

  // 【可选】约束和规则
  "constraints": [
    "规则1",
    "规则2"
  ],

  // 【可选】示例（few-shot 时使用）
  "examples": [
    {"input": "...", "output": "..."}
  ],

  // 【可选】链式推理（Chain 模式时使用）
  "reasoning": {
    "steps": ["思考步骤1", "思考步骤2"],
    "final_output": "最终输出的字段要求"
  }
}
```

### Step 4 → 解释给用户听

生成后，**逐段解释**每个字段的含义和作用：

> **task** → 告诉 AI 要做什么，是整个提示词的锚点
> **output_format.schema** → 定义输出的 JSON 结构，每个字段标注了类型和说明
> **constraints** → 约束条件，防止 AI 编造不存在的数据
>
> 你看看这个结构对不对？要加示例、改字段、加约束吗？

### Step 5 → 用户审核 → 调整

用户提出修改意见后，直接调整 JSON prompt 的对应部分，重新展示。循环直到用户说「行了」。

## 编写原则

1. **不套模板** — 每次根据用户的具体需求从头生成，不是从固定模板里填坑
2. **先结构后细节** — 先搭整体框架（task + output_format），再细化字段和约束
3. **解释要易懂** — 不说「这是 schema 定义」这种术语，说「这个字段定义输出里要包含什么」
4. **坑点前置** — 生成后主动指出可能的坑（字段缺失处理、枚举值范围、JSON 转义等）
5. **默认用中文** — 生成的 JSON prompt 字段名和说明默认用中文，除非用户指定用英文
6. **约束宁多勿少** — 防 AI 幻觉的约束（如「缺失字段用 null，不要编造」）默认加上，用户嫌多再减
7. **区分 output 和 internal** — 如果用户需要 AI 先思考再输出，必须用 Chain 模式，在 prompt 里显式写明推理步骤和输出步骤的分界

## 常用防坑约束（默认自动添加，用户可要求删除）

- 缺失字段用 `null`，不要编造
- 仅提取原文明确写出的信息，不要推理
- 输出 JSON 不要加 markdown 代码块包裹（除非用户特别要求）
- 枚举值严格区分大小写
- 所有字符串不要前后空格
